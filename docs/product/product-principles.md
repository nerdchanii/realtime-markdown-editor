# docs/product/product-principles.md

## 목적

이 문서는 제품 기능을 설계하고 설명할 때 유지할 공통 원칙을 정리한다. 기준은 요구사항 통과 여부가
아니라, 사용자가 팀 문서를 안정적으로 작성하고 함께 관리할 수 있는지다.

## 제품 원칙

- 첫 화면은 문서를 작성하고 협업하는 에디터 경험이어야 한다.
- 사용자는 현재 워크스페이스, 프로젝트, 문서, 본인 계정을 즉시 이해할 수 있어야 한다.
- 작성 중인 내용, 오프라인 임시 저장본, 체크포인트, 내보내기 결과는 서로 충돌하지 않는 저장 경계를 가진다.
- 구성원 presence와 이력은 문서 작성 흐름을 방해하지 않고 맥락을 보강해야 한다.
- Markdown은 리치 작성 경험 안에서도 이동 가능한 문서 형식으로 남아야 한다.
- 제품 문서는 기능이 해결하는 사용자 문제와 연결 흐름을 설명해야 한다.

## 기능 설명 방식

- 기능 이름은 사용자가 하는 행동으로 쓴다.
- 내부 ID, 테스트명, 요구사항 번호는 제품 설명의 주어로 쓰지 않는다.
- 보류된 기능은 “미달”이 아니라 “향후 확장”으로 설명한다.
- 구현 세부 기술은 사용자 흐름을 설명하는 데 필요한 만큼만 연결한다.
