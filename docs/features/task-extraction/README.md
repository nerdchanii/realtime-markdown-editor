# F-TASK-EXTRACTION: Task Extraction Backlog

## Purpose

Preserve the idea of deriving actionable work from document text while keeping the MVP focused on the required collaborative editor.

## MVP Scope

- No MVP implementation.
- Treat task extraction as a future product capability.
- Keep task metadata parsing dependent on a later task extraction decision.

## Out of Scope / Backlog

- Automatic extraction of Markdown task list items into a task panel.
- Parsing `@owner`, `#tag`, and `due:YYYY-MM-DD`.
- Task assignment, status workflows, and reminders.
- Cross-document task aggregation.

## Linked Requirement IDs

- `BL-01`
- `BL-02`

## Acceptance Summary

Task extraction and task metadata parsing are visibly deferred, and no MVP requirement depends on them.

## Open Questions / Research

- Whether task extraction should be rule-based, editor-structured, or assisted by later automation.
- Which task syntax should be supported if this returns to MVP scope.
